# 首次试用指南

用一次最多 20 分钟的试用，检查 Research Workbench 能否帮助你整理研究依据、理解候选问题并决定下一步。到点即可停止；没有报告、没有帮助或操作失败，都值得记录。

界面目前以中文为主，启动需要 Python 3.11 或更高版本。从开始写下试用前的问题与原计划时计时，之后阅读 [README 的下载与启动说明](../README.md#try-it-without-an-api-key)、下载代码、安装 Python（如需要）和等待模型都计入 20 分钟。基础工作台无需安装额外包，也不要求配置 API key；分析时可以把导出的提示交给你常用的模型服务，该服务自身的使用限制与费用仍然适用。

## 已有问题和论文

准备一个真实疑问、主要研究条件，以及 1–3 篇你熟悉的公开论文。这些材料足以开始一次操作试用，是否足以判断课题仍需看具体问题。这里的时间是观察安排，不是完成速度承诺。

| 用时安排 | 做什么 | 记录什么 |
|---|---|---|
| 0–2 分钟 | 写下真实问题、已知限制，以及目前准备采取的下一步。 | 试用前的原计划；未知条件留空。 |
| 2–6 分钟 | 从 README 下载或克隆代码，启动工作台。 | 首次卡点、错误提示和是否求助。缺少 Python 也计入体验。 |
| 6–10 分钟 | 填写问题与条件，加入论文摘要、自己的笔记或 PDF 片段。 | 材料是否容易加入，是否能识别来源和阅读范围。 |
| 10–15 分钟 | 导出提示，在自己常用的模型中获得回答，再导入 JSON。 | 使用的模型、等待、格式错误和人工协助；保留第一次结果。 |
| 15–18 分钟 | 找到报告里第一条影响判断的论断，点击引用，对照实际提供的材料。 | 支持、不支持或无法判断，并指出对应位置。 |
| 18–20 分钟 | 说明准备继续、修改、停止还是补充证据。 | 哪一句影响了决定，或为什么没有帮助。 |

超过 20 分钟时，记录停在哪一步和原因。你可以之后继续，但后续尝试单独记录，不把多次尝试合并成一次成功。抽查一条论断只说明这一条的情况；“打算做实验”与“已经执行实验”也分别记录。

## 只有兴趣方向

如果还没读过论文，先展开材料区的 **还没读过论文？从这里开始**。当前试点是深度强化学习。

找到概念引导，打开一份材料，加入一条摘要转述，填写自己的兴趣并保存项目或导出提示。检查自己能否分清“助手整理的摘要”与“自己读过的论文”。读不懂术语或找不到下一步时，直接记录卡点即可。

这条路径主要检查入门入口是否好用。加入材料不代表已阅读，保存或导出也不代表完成了科研选题。

## 留下反馈

使用 [首次试用反馈](https://github.com/wangxin-cell/research-workbench/issues/new?template=first_try.yml) 记录起点、最后做到哪一步和一处具体体验。这个表单不要求你先生成报告。提交 GitHub issue 需要登录账号；也可以在看到项目介绍的社区评论区，用相同的三项内容反馈。

已有报告、希望指出无依据的结论或遗漏的已有工作时，可使用更详细的 [研究反馈表](https://github.com/wangxin-cell/research-workbench/issues/new?template=research_feedback.yml)。公开反馈使用简短转述和公开链接即可；完整研究材料可以保留在本机。

## 维护者如何使用这些反馈

首次计划观察 5 位已有真实问题和论文的研究者，并将零论文入口、内置演示和开发者自测单独记录。记录是否启动、在哪一步停止、实际耗时及协助情况；重复尝试不增加独立参与者数量。通过社区自愿报名获得的反馈不代表所有研究者。

未提供耗时或协助情况的反馈仍保留，但不能计为已满足“20 分钟无协助完成”。自行报告与现场观察分开记录。

以下门槛用于首轮开发排序，开始前确定；没有统计代表性，不构成科研效果评价。

| 观察指标 | 内部行动门槛 |
|---|---|
| 完整流程可达性 | 5 次核心试用中，至少 4 次在 20 分钟内无协助走到真实材料对应的报告，再扩大邀请。同一环节让 2 人卡住，优先修复。 |
| 引用核查可操作性 | 至少 4 位生成报告的参与者能够定位一条关键论断的材料，并说明支持、不支持或无法判断及理由。其他未核查内容保持未知。发现经核实的关键编造或硬约束冲突，优先处理。 |
| 具体决策线索 | 流程门槛达到后，至少 3 人能指出具体输出怎样补充、改变或支持原计划，并说清下一步；否则先调整输入或输出，暂不扩充领域。 |

这些记录属于开发反馈，不自动加入正式案例集或保留组。评价科研质量仍需冻结材料与标准、安排基线比较和领域评审，见 [评审操作说明](评审操作说明.md)。
